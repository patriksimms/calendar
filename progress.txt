## EE-110 — Modern examples, CI, migration docs (2026-05-05)

Replaced the legacy rc-tools example workflow with a Vite React 19 demo app,
added GitHub Actions CI for Node 20 + 22, and rewrote the README around the
modern toolchain.

What landed:
- Removed every legacy `examples/*.html` + `examples/*.js` file.
- New standalone Vite app under `examples/`:
  - `examples/package.json` (private, Vite 6, React 19, types, plus the demo-only
    deps `rc-dialog`, `rc-select`, `rc-time-picker`).
  - `examples/vite.config.ts` aliases `rc-calendar`, `rc-calendar/src/*`, and
    `rc-calendar/assets/*` to the local sources so the demo exercises the
    package through the live `src/` tree.
  - `examples/tsconfig.json` with `jsx: react-jsx`, bundler module resolution.
  - `examples/index.html` mounts a React 19 root via `<script type="module">`.
  - `examples/src/main.tsx` boots with `createRoot` (no `ReactDOM.render`).
  - `examples/src/App.tsx` is a hash-routed demo switcher.
  - `examples/src/demos/*.tsx`: Basic, RangeCalendar, WeekCalendar,
    MonthCalendar, FullCalendar, CustomClearIcon, Container, ControlPanel,
    StartEnd, StartEndRange — covering every legacy scenario.
  - All demos import the package via `rc-calendar/src/*` (Calendar,
    RangeCalendar, MonthCalendar, FullCalendar, Picker, locale/en_US).
- `.github/workflows/ci.yml` runs install/lint/typecheck/test/build/pack on
  Node 20 + 22 via `actions/setup-node` + `oven-sh/setup-bun` (frozen lockfile
  install). Triggers on push to `main`/`master`/`9.x`/`10.x` and on PRs.
- README rewritten:
  - Documents the modern stack: tsdown, vite, vitest + RTL, oxlint/oxfmt, bun,
    React 19 peer support.
  - Adds a Development section covering install/typecheck/lint/test/build,
    plus a Demo section showing `cd examples && bun install && bun run dev`.
  - Style import section covers both `assets/index.less` and the compiled
    `assets/index.css` artefact.
  - Browser support reframed as evergreen Chrome/Firefox/Safari/Edge — IE9
    claim removed.
  - Removed the broken Travis/Codecov/LGTM/etc. badges that pointed at dead
    services.
  - Avoids release/version/CHANGELOG language in the dev docs (per AC).
- New TDD smoke tests under `tests/`:
  - `examples.app.smoke.vitest.ts` — asserts the Vite + React 19 deps,
    `vite.config.*`, root mount, `createRoot` use, no `ReactDOM.render`
    anywhere under `examples/`, and that all ten demo files exist.
  - `ci.workflow.vitest.ts` — parses `.github/workflows/ci.yml` and asserts
    the install/lint/typecheck/test/build/`npm pack --dry-run` pipeline runs
    on a Node 20 + 22 matrix and triggers on push + pull_request.
  - `readme.docs.vitest.ts` — asserts README mentions the modern toolchain
    (tsdown/vite/vitest/oxlint), the asset import path, the demo workflow,
    the testing approach, evergreen browsers (no IE9), and that the dev
    section is free of release/version/CHANGELOG wording.

Notes for the next person:
- The examples app is intentionally separate from the root install — `bun
  install` at the repo root does NOT install Vite or the demo-only deps.
  `cd examples && bun install` is required before `bun run dev`.
- The Vite alias `rc-calendar -> ../src` means the demo always runs against
  the live source tree (no `bun run build` needed for the demo). The package
  smoke test still drives the compiled artefacts.
- CI uses `npm pack --dry-run` (not `bun pm pack`) because `npm pack` is the
  reference contract for what gets published to the npm registry.
- React 19 peer + the findDOMNode polyfill from EE-109 still apply — no
  changes needed there.
- Locales currently default to en_US in the demos; previously demos toggled
  zh_CN via `?cn` query param. That toggle is dropped — keeping examples
  focused on the English happy path. Any locale can be re-imported per demo.

## EE-109 — React 19-compatible runtime + RTL test foundation (2026-05-05)

Made calendar runtime + tests React 19-compatible.

What landed:
- Bumped peer/dev React + React DOM to ^19; added @testing-library/react,
  @testing-library/jest-dom, @testing-library/dom, jsdom for the new test path.
- Removed dead `getRootDOMNode = () => ReactDOM.findDOMNode(this)` methods from
  `src/Calendar.jsx`, `src/calendar/CalendarFooter.jsx`, and
  `src/date/DateInput.jsx`. They had no callers and dragged in findDOMNode (which
  React 19 no longer exports).
- `src/Picker.jsx` no longer calls `ReactDOM.findDOMNode(this).focus()` on
  ESC/clear/ok/today close. It now stores a ref to the user-rendered child via
  `cloneElement({ ref: this.saveTriggerRef })` and calls
  `this.triggerInstance.focus()`.
- `src/Calendar.jsx` no longer relies on `DateInput.getInstance()`. It holds a
  ref to its own DateInput and calls `getInputDOMNode()` on it for the
  `componentDidMount` focusElement save and the `onBlur` activeElement check.
  DateInput keeps the legacy static `getInstance()` for backward compat (still
  used by no-one inside this package), but routes its own focus + DOM node
  access through an instance field.
- `src/util/findDOMNodePolyfill.js` ships a small fiber-walking polyfill that
  re-installs `ReactDOM.findDOMNode` if React 19 has removed it. It is loaded
  by `src/index.js` and by the test setup so transitive deps that still call
  `findDOMNode` (notably `rc-trigger` 2.x and `rc-align` 2.x, which we keep
  pinned per package.json) keep working at runtime under React 19. If those
  packages are upgraded to versions that don't call findDOMNode, the polyfill
  becomes a no-op and can be removed.
- New Vitest + RTL test foundation (`tests/*.dom.vitest.tsx`):
  - `Calendar.dom.vitest.tsx` — renders the date panel; click selects a date;
    today button selects today; clear button calls onClear + onSelect(null);
    disabledDate prevents selection; OK button fires onOk(selectedValue);
    ArrowDown moves selection forward by a week; clicking the month-select
    opens the month panel; custom locale renders translated text.
  - `DateInput.dom.vitest.tsx` — typing valid date emits onChange; bad input
    flags invalid; disabled date typed in input is rejected; clear button
    empties the input; Enter fires onSelect.
  - `Picker.dom.vitest.tsx` — clicking the trigger opens the calendar; ESC
    closes it AND restores focus to the trigger (asserts via
    `document.activeElement`); ArrowDown opens a closed picker; selecting a
    cell emits onChange; onOpenChange fires on visibility transitions.
  - `RangeCalendar.dom.vitest.tsx` — renders default and custom separator;
    selects start then end; right-panel next-month button advances to May;
    disabled cells get the disabled class; showClear icon fires onClear; today
    button updates the visible panel.
  - `TimeIntegration.dom.vitest.tsx` — time-picker button toggles the
    time-picker panel; selecting a date with a time-picker default value
    bakes the time into the resulting input string.
- `vitest.config.ts` now uses `environment: 'jsdom'` (vitest v4 dropped
  `environmentMatchGlobs`), pulls JSX through oxc with `runtime: 'automatic'`,
  and points at `tests/vitest.setup.ts` (which loads jest-dom matchers and the
  findDOMNode polyfill, and runs `cleanup()` after each test).
- Retired the legacy Enzyme/Jest suite per the EE-109 acceptance criteria:
  removed all `tests/*.spec.{js,jsx}` files, `tests/__snapshots__/`,
  `tests/__mocks__/`, `tests/EnzymeExt.js`, `tests/setup.js`, the `jest`
  config + `test:jest` + `coverage` (jest) script in `package.json`, and the
  `enzyme*`, `jest`, `enzyme-to-json`, `mockdate` dev deps. `bun run test`
  is the only test path now (53 tests, all green, includes the prior package
  smoke test).

Notes for the next person:
- Date semantics in tests assume the system clock. The old Jest setup pinned
  `moment` to 2017-03-29 via `mockdate`. The new RTL tests pass explicit dates
  to `defaultValue`/`defaultSelectedValue`, so they don't need a frozen clock.
- The findDOMNode polyfill is a compatibility shim for transitive deps. If you
  upgrade `rc-trigger` to v5+/`@rc-component/trigger` you can drop both the
  polyfill module import in `src/index.js` and the one in the test setup.
- The PRD (#107) lists user stories 11/12/14–22/30–33/40 covered by this slice.
  The new vitest suite asserts external DOM behavior + callbacks, never
  Enzyme-style internal state — those are the AC for "Tests assert external
  DOM behavior and callbacks rather than Enzyme implementation internals."

## EE-108 — Modernize calendar package build (2026-05-05)

Replaced legacy rc-tools/Babel build with tsdown (rolldown-based).

What landed:
- `tsdown.config.ts` emits CJS to `lib/` and ESM to `es/` in unbundle mode (one
  output per source file, preserving deep-import paths).
- Both formats output `.js` so consumers' documented `lib/RangeCalendar`,
  `lib/locale/en_US`, etc. paths keep resolving.
- Less compile step is `lessc assets/index.less assets/index.css`. Less sources
  remain published artifacts under `assets/`.
- `package.json`: `build` is `tsdown && lessc ...`; added `typecheck`,
  `peerDependencies` for React 19 (`>=16.9.0 || ^17 || ^18 || ^19`); dropped
  `rc-tools`, `babel-runtime`, and `dist` from `files`.
- Smoke test: `tests/package.smoke.vitest.ts` runs `bun run build` once and
  asserts CJS/ESM defaults, deep imports, locale imports, less + compiled CSS,
  the `index.d.ts` entrypoint, and the published manifest.
- Renamed JSX-bearing `.js` source files to `.jsx` (`RangeCalendar.jsx`,
  `date/DateInput.jsx`, `mixin/CalendarMixin.jsx`, `month/MonthTable.jsx`,
  `range-calendar/CalendarPart.jsx`) so oxc parses them. Output paths are
  unaffected — consumers always import the compiled `.js`.
- `tsconfig.json` JSX is now `react` (was `preserve`) so the same config drives
  both `tsc --noEmit` and tsdown's transform.

Notes for the next person:
- The legacy jest+enzyme suite (`bun run test:jest`) is still on React 16 and
  is NOT touched by this slice — it is a separate migration. The vitest run
  (`bun run test`) is the verification path used here.
- tsdown emits a small `lib/_virtual/_rolldown/runtime.js` helper used by the
  CJS interop. It ships as part of `lib/` and is required by the compiled
  modules; do not delete it manually.
- If you add new JSX in a `.js` file under `src/`, rename it to `.jsx` or oxc
  will throw `[PARSE_ERROR] JSX syntax is disabled`.
